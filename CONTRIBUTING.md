# Contributing to HN BlackBox

Thanks for taking an interest in HN BlackBox.

## Before opening a pull request

- Explain what the change does and why it is useful.
- Keep security-sensitive functionality defensive and authorized.
- Add tests for new behavior where practical.
- Do not commit credentials, tokens, private keys, or personal data that is not intended for the repository.
- Keep the interface consistent with the existing visual language.

## Pull requests

A good pull request should contain:

1. A short description of the problem.
2. The implementation approach.
3. Tests performed.
4. Any known limitations.

For larger changes, open an issue first so the architecture can be discussed before implementation.
